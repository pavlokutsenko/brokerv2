# PriceCheck Launcher и Collector

Два независимых Windows-приложения на общей кодовой базе:

- **Launcher** — запуск игровых окон, HWID/прокси, автовход, ротация и перезапуск.
- **Collector** — тот же запуск плюс радар, брокер, проверка цен и отправка на сервер.

На компьютере со сбором нужен только Collector. Launcher не содержит
`PriceCheck.Collection`, BrokerWorker, Python или подключения к API рынка.
Обе поставки self-contained; EXE лежит прямо в корне каждого ZIP.
Настройки разделены: `%LOCALAPPDATA%\PriceCheckLauncher` и
`%LOCALAPPDATA%\PriceCheckCollector`. [Перенос и устройство поставок](docs/DESKTOP_PACKAGES.md).
Сервер и сайт находятся отдельно в `C:\PriceCheck`; клиентский репозиторий
не содержит серверной поставки, установщика БД или миграций.
[Состав репозитория](docs/REPOSITORY_LAYOUT.md).

Состояние сборок, завершённая интеграция сайта и оставшиеся игровые проверки:
[актуальный checkpoint](docs/RESUME.md).

Текущая сборка реализует единый профиль рынка:

В Collector запуск и сбор разделены на два модуля в одном окне: **Launch** управляет
игрой, шаблоном и прокси; **Collection** отдельно подключает чтение персонажа,
радар и сбор цен. `Disconnect reader` оставляет игру открытой. Закрытие всего
приложения завершает запущенные им игры. Подробности —
[границы модулей](docs/analysis/module-separation/README.md).

- несколько профилей рынков;
- папка клиента и роль для каждого профиля;
- запуск клиента из коллектора и автоматическая привязка нового `lu4.bin`;
- reader только у защищённого процесса, запущенного этим приложением;
- обзор радара и счётчики трейдеров;
- встроенный автономный брокерный worker для типов лавок 1, 3 и 8;
- локальную очередь проверок с сохранением истории и общим серверным состоянием;
- цикл возврата в ручной центр, брокерного сбора и плавного чтения цен на ходу;
- отдельные PID, маршруты и остановку для параллельных профилей;
- ручной быстрый режим чтения лавок во время движения пользователя.

Новый цикл включается через **Collection → Start collection** после подключения
reader и назначения центра кнопкой **Set current**. Брокер обновляет состав рынка;
новые лавки с радара принимаются сразу после чтения точных цен. Брокерное
отсутствие не снимает лавку: требуется свежее явное закрытие из сохранённого
центра. Полный валидный состав торговца разрешает убрать отсутствующие позиции;
частичный состав сохраняет их.
Остатки обновляются без посещения, цены — выборочными проходами возле лавок.
См. [настройку и ограничения](docs/COLLECTION_CYCLE.md) и
[подтверждённые проверки прежних сборок](docs/analysis/market-cycle/PROGRESS.md).
Проверен короткий живой проход в Giran; одновременный бег двух реальных клиентов
и многодневная работа ещё не проверены. Исследовательский ручной режим
`manual-passby-shops.ps1` сохранён. Текущая поставка: [DESKTOP_PACKAGES.md](docs/DESKTOP_PACKAGES.md).

## Сборка

Сборка обеих приложений и сразу двух чистых портативных архивов (PowerShell 7):

```powershell
cd C:\broker
.\build.ps1
```

Результат: `release\PriceCheckLauncher\PriceCheck.Launcher.exe`,
`release\PriceCheckCollector\PriceCheck.Collector.exe` и два ZIP с SHA-256 в
`release\packages`. Полностью распакуйте нужный ZIP и запускайте EXE из корня.
Игра устанавливается отдельно. Для обычных архивов Setup не требуется.
При переносе настроек копируйте оба JSON-файла, сохраняя ID и seed HWID;
пароли на новом ПК вводятся заново из-за DPAPI. Сервер и база в ZIP не входят.

Для локальной разработки с запуском Collector:

```powershell
cd C:\broker
.\dev.ps1 run
```

Это основной цикл разработки: старый экземпляр коллектора останавливается,
изменённые части собираются, приложение запускается через локальную задачу с
правами администратора, после чего команда ждёт основное окно и состояние
`RUNNING` у LU4Memory. Неизменённый BrokerWorker повторно через PyInstaller не
собирается.

```powershell
.\dev.ps1 restart  # перезапуск без сборки
.\dev.ps1 status   # процессы, задача, драйвер и последний bootstrap-лог
.\dev.ps1 full     # принудительная полная сборка BrokerWorker и приложения
.\dev.ps1 stop     # остановить Collector и upload worker
```

Подробности и восстановление dev-задачи описаны в
[`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md).

Готовые переносимые сборки появляются в `release\PriceCheckLauncher` и
`release\PriceCheckCollector`. `build.ps1 -SkipPackages` пропускает только ZIP;
`-OutputDirectory` задаёт каталог Collector, `-LauncherOutputDirectory` — Launcher,
`-PackageDirectory` — каталог архивов. Закройте приложение перед обновлением его release.

Сборка публикуется через проверенную копию с принудительным сбросом файлов на
диск и атомарной заменой. `dev.ps1 restart` и `start-collector.ps1` перед запуском
восстанавливают повреждённые или недописанные файлы по сохранённому manifest.
Резервные версии находятся рядом с пакетом в `PriceCheckCollector.package-recovery`.
Карты и правила движения разделены по городам в [maps](maps/README.md).

Для отдельной повторной упаковки одного продукта выполните в PowerShell 7:

```powershell
.\scripts\package-portable.ps1 -Product Launcher
.\scripts\package-portable.ps1 -Product Collector
```

Скрипт вызывает `build.ps1` с отдельным каталогом публикации, проверяет
runtime и создаёт выбранный архив в `release\packages` вместе с SHA-256. Текущая
работающая release не заменяется. В архив входят `README-FIRST.txt`,
`Verify-Package.ps1`, запуск с метаданными `Start-WithDiagnostics.ps1`
и сбор выбранных журналов `Collect-Diagnostics.ps1`. Профили, пароли,
результаты сбора и игра в архив не входят; на другом ПК настройте их отдельно.
Проверка упаковки не заменяет фактический запуск на другом ПК.

На компьютере коллектора не требуются установленный .NET, Python или
исследовательская папка `driver`: необходимые runtime, broker worker и
проверенный драйвер LU4Memory с загрузчиком уже находятся внутри поставки.
При запуске Windows запрашивает UAC для доступа к устройству драйвера. После
перезагрузки коллектор сам загружает LU4Memory и только затем открывает
интерфейс. Настройки сохраняются в
`%LOCALAPPDATA%\PriceCheckCollector\profiles.json`. Старый переносимый файл
автоматически копируется туда при первом запуске.

Для запуска обязательно выберите шаблон с включёнными **HWID и прокси**.
Без него или при проваленной проверке игра не запускается; ошибку показывает
панель Launch. Индикаторы подтверждают реальные ответы HWID hooks и применение
world identity, WFP-защиту и двусторонний трафик через CONNECT. Проверки продолжаются
при ручном входе, выборе/смене персонажа и во время работы; ошибка останавливает
клиент и сбор. [Устройство проверок и границы](docs/LAUNCH_PROTECTION.md).

Во вкладке
«Шаблоны» видны 20 генерируемых значений SMBIOS, диска, сети и реестра;
их можно закрепить либо обновлять при каждом запуске. Кнопка сканирования
показывает исходные значения текущего ПК, предварительный результат и охват
агента для конкретных Windows API. Обнаружение поля не означает подмену при
прямом обращении клиента к драйверу, WMI или прошивке. HTTP CONNECT-прокси с
логином и паролем обязателен. До выполнения кода клиента драйвер
перенаправляет IPv4/TCP-соединения на локальный сервер Launcher/Collector,
который открывает CONNECT через указанный прокси. Прямые подключения,
UDP/raw и IPv6 игровых процессов блокируются. Старые игровые проверки прокси
прошли до мира; новая строгая защита проверена на тестовых процессах и требует
отдельной live-приёмки в игре.
Шаблоны хранятся в
`%LOCALAPPDATA%\PriceCheckCollector\launch-templates.json`; пароль защищён DPAPI
текущего пользователя Windows. Прежние настройки запуска профиля переносятся
в шаблон автоматически. Для HWID модуль загружает `PriceCheck.ClientAgent.dll`
в конечный GUI-процесс через оконный хук Windows. Прокси работает через WFP
без подмены `recv` клиента.
Файл `version.dll` в каталог клиента не добавляется. Если он остался от
предыдущей сборки PriceCheck, модуль удалит его после проверки хеша; чужой файл
не тронет. Драйвер LU4Memory обслуживает packet radar, broker и WFP.
Проверка нативного агента на отдельном тестовом процессе описана в
[`docs/analysis/hardshift-launch/README.md`](docs/analysis/hardshift-launch/README.md).
Прогон прокси и замеченное окно Active Anticheat описаны в
[`docs/analysis/wfp-proxy/README.md`](docs/analysis/wfp-proxy/README.md).

Для каждого экземпляра можно включить автовход и задать логин, пароль,
сервер Gamma и номер слота персонажа. После запуска и установки packet radar
коллектор вызывает функции входа внутри клиента и выбирает сервер и слот.
Пароль профиля защищён Windows DPAPI. Программный вход проверен на конкретной
сборке LU4; другой бинарник должен быть исследован отдельно. Внутренние ID
других серверов пока не подтверждены. Подробности — в
[`docs/analysis/client-autologin/README.md`](docs/analysis/client-autologin/README.md).

Границы модулей и правила для будущего драйверного runtime описаны в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

Исходники, протокол, воспроизводимая сборка и проверенный бинарник нашего
драйвера находятся в [`native/LU4Memory`](native/LU4Memory). Драйвер теперь
является частью этого репозитория; старая исследовательская папка для его
сборки больше не нужна как источник истины.
