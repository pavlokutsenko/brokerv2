# PriceCheck Collector

Новый независимый Windows-коллектор для нескольких рынков и нескольких
игровых клиентов на одном компьютере.

Текущая сборка реализует единый профиль рынка:

Запуск и сбор теперь разделены на два модуля в одном окне: **Launch** управляет
игрой, шаблоном и прокси; **Collection** отдельно подключает чтение персонажа,
радар и сбор цен. `Disconnect reader` оставляет игру открытой. Закрытие всего
приложения завершает запущенные им игры. Разделение проверено сборкой и
подставными сеансами; новая версия ещё не прошла live-контроль. Подробности —
[границы модулей](docs/analysis/module-separation/README.md).

- несколько профилей рынков;
- папка клиента и роль для каждого профиля;
- запуск клиента из коллектора и автоматическая привязка нового `lu4.bin`;
- ручная привязка уже запущенного свободного процесса;
- обзор радара и счётчики трейдеров;
- встроенный автономный брокерный worker для типов лавок 1, 3 и 8;
- локальную очередь точных проверок цен;
- ручной быстрый режим чтения лавок во время движения пользователя.

Автоматический маршрут остаётся экспериментальным. Текущий проверенный режим —
`manual-passby-shops.ps1`: пользователь ведёт персонажа, а worker без UI читает
лавки, попавшие в радиус. Текущее состояние и точные команды продолжения
записаны в [`docs/RESUME.md`](docs/RESUME.md).

## Сборка

```powershell
cd C:\broker
.\dev.ps1 run
```

Это основной цикл разработки: старый экземпляр коллектора останавливается,
изменённые части собираются, приложение запускается через локальную задачу с
правами администратора, после чего команда ждёт основное окно и состояние
`RUNNING` у LU4Memory. Неизменённый BrokerWorker повторно через PyInstaller не
собирается.

```powershell
.\dev.ps1 restart  # перезапуск без сборки
.\dev.ps1 status   # процессы, задача, драйвер и последний bootstrap-лог
.\dev.ps1 full     # принудительная полная сборка BrokerWorker и приложения
.\dev.ps1 stop     # остановить Collector и upload worker
```

Подробности и восстановление dev-задачи описаны в
[`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md).

Готовая переносимая сборка появляется в `release\PriceCheckCollector`.

Для чистого ZIP на другой ПК выполните в PowerShell 7:

```powershell
.\scripts\package-portable.ps1
```

Скрипт вызывает `build.ps1` с отдельным каталогом публикации, проверяет
runtime и создаёт архив в `release\packages` вместе с SHA-256. Текущая
работающая release не заменяется. В архив входят `README-FIRST.txt`,
`Verify-Package.ps1`, запуск с метаданными `Start-WithDiagnostics.ps1`
и сбор выбранных журналов `Collect-Diagnostics.ps1`. Профили, пароли,
результаты сбора и игра в архив не входят; на другом ПК настройте их отдельно.
Проверка упаковки не заменяет фактический запуск на другом ПК.

На компьютере коллектора не требуются установленный .NET, Python или
исследовательская папка `driver`: необходимые runtime, broker worker и
проверенный драйвер LU4Memory с загрузчиком уже находятся внутри поставки.
При запуске Windows запрашивает UAC для доступа к устройству драйвера. После
перезагрузки коллектор сам загружает LU4Memory и только затем открывает
интерфейс. Настройки сохраняются в
`%LOCALAPPDATA%\PriceCheckCollector\profiles.json`. Старый переносимый файл
автоматически копируется туда при первом запуске.

У каждого экземпляра выбирается шаблон запуска или «Без шаблона». Во вкладке
«Шаблоны» видны 20 генерируемых значений SMBIOS, диска, сети и реестра;
их можно закрепить либо обновлять при каждом запуске. Кнопка сканирования
показывает исходные значения текущего ПК, предварительный результат и охват
агента для конкретных Windows API. Обнаружение поля не означает подмену при
прямом обращении клиента к драйверу, WMI или прошивке. HTTP CONNECT-прокси с
логином и паролем включается отдельно и необязателен. Для выбранного PID
драйвер перенаправляет IPv4/TCP-соединения на локальный сервер Collector,
который открывает CONNECT через указанный прокси. Локальный тест прошёл до
мира LU4; указанный внешний прокси прошёл вход и обмен данными с world-сервером.
Шаблоны хранятся в
`%LOCALAPPDATA%\PriceCheckCollector\launch-templates.json`; пароль защищён DPAPI
текущего пользователя Windows. Прежние настройки запуска профиля переносятся
в шаблон автоматически. Для HWID модуль загружает `PriceCheck.ClientAgent.dll`
в конечный GUI-процесс через оконный хук Windows. Прокси работает через WFP
без подмены `recv` клиента.
Файл `version.dll` в каталог клиента не добавляется. Если он остался от
предыдущей сборки PriceCheck, модуль удалит его после проверки хеша; чужой файл
не тронет. Драйвер LU4Memory обслуживает packet radar, broker и WFP.
Проверка нативного агента на отдельном тестовом процессе описана в
[`docs/analysis/hardshift-launch/README.md`](docs/analysis/hardshift-launch/README.md).
Прогон прокси и замеченное окно Active Anticheat описаны в
[`docs/analysis/wfp-proxy/README.md`](docs/analysis/wfp-proxy/README.md).

Для каждого экземпляра можно включить автовход и задать логин, пароль,
сервер Gamma и номер слота персонажа. После запуска и установки packet radar
коллектор вызывает функции входа внутри клиента и выбирает сервер и слот.
Пароль профиля защищён Windows DPAPI. Программный вход проверен на конкретной
сборке LU4; другой бинарник должен быть исследован отдельно. Внутренние ID
других серверов пока не подтверждены. Подробности — в
[`docs/analysis/client-autologin/README.md`](docs/analysis/client-autologin/README.md).

Границы модулей и правила для будущего драйверного runtime описаны в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

Исходники, протокол, воспроизводимая сборка и проверенный бинарник нашего
драйвера находятся в [`native/LU4Memory`](native/LU4Memory). Драйвер теперь
является частью этого репозитория; старая исследовательская папка для его
сборки больше не нужна как источник истины.
