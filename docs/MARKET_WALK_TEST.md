# Тест плавного обхода рынка

Проверка **четырёх одиночных целей в разных углах**:

```powershell
& "C:\broker\test-market-walk.ps1" -SingleTargets
```

Режим сам выбирает четыре видимые лавки, предпочитая менее плотное окружение.
К каждой строится касательный вход, дуга примерно в 72 единицах от трейдера
и выход дальше по маршруту. Целью движения служат точки прохода, а не позиция
трейдера. Планировщик держит минимум 55 единиц; исполнитель запрещает срезать
путь через круг радиуса 45. Читаются только четыре выбранных имени. Персонаж
продолжает движение после чтения; недоступная лавка пропускается. Сохраняется
отмена цели на сервере после каждого запроса и живые проверки препятствий.
Это тест по текущей зоне видимости и сохранённой геометрии, не полный рынок.

`*.result.json / single_targets` содержит фактическое минимальное сближение,
дистанцию чтения, число лотов и перемещение в течение примерно секунды после
ответа. `-PlanOnly` позволяет проверить выбранные имена и маршрут до движения.
Режим не совмещается с `-ObstacleCourse`/`-ResumeResult`; обычные препятствия
обходятся всегда. Радиус чтения для такого прохода должен быть не меньше 75.

Проверка 25.09.2026: четыре лавки в четырёх углах, 22 лота с точными ценами,
91 секунда, без застреваний. Чтение с 62–71 единицы, ближайшее сближение
56–59 единиц. После каждого чтения движение продолжилось, все четыре отмены
цели подтверждены сервером. [Сохранённый путь](../maps/Giran/giran-single-targets-2026-09-25.png).

Чтение лавок, оказавшихся рядом с маршрутом, включается отдельно:

```powershell
& "C:\broker\test-market-walk.ps1" -ReadShops
```

Радиус чтения по умолчанию **85**, разрешено `-ShopRadius 1..95`.
Режим совместим с `-ObstacleCourse` и `-DurationSeconds`. Обнаружение и ответы читаются
в отдельном потоке: ожидание ответа не останавливает движение. Перед каждым
из двух обычных действий выбора цели заново проверяются ID, имя, тип лавки,
расстояние и этаж. Радиус проверяется по позиции клиента **и последней позиции
из ответов сервера**: клиент может заметно опережать сервер. Вышедшие из радиуса
и не ответившие за две секунды лавки
пропускаются; повторная попытка возможна через 30 секунд. Четыре запроса могут
ожидать ответа одновременно. Успешная лавка читается один раз за запуск.

Повторное действие действительно вызывает подход к трейдеру. На время этого
режима обработчик входящего MoveToObject (`0x72`) пропускает подход **только
нашего персонажа**, сохраняя движение других игроков. Панели магазина/цели
не открываются. Обычные серверные действия идут строго в порядке: **выбор →
повторное действие → отмена цели на сервере → команда маршрута**. Не чаще одной
такой серии за 0,6 с. Это не режим «без таргета»: кратковременный серверный выбор
есть, после него отправляется обычная отмена `0x48`.

Ответ отмены `0x24 / TargetUnselect_Order` проходит штатно и учитывается отдельно.
Сразу после него исполнитель обновляет направление, чтобы отмена не оставляла
короткую остановку. Внешняя смена цели и F8 по-прежнему завершают проход. В режиме
чтения финальная остановка требует 1,5 с подтверждённого покоя из-за поздних ответов.

`*.shops.jsonl` сохраняет запросы с фактическими координатами/расстоянием,
ответы, лоты, источник точности и таймауты. Для обычных sell-лавок `wire_int64`
означает цену и количество из проверенного ответа A1 без сужения до int32.
Остальные форматы сохраняются как `client_int32_unverified`: для очень больших
цен/остатков их сетевой формат ещё требует проверки. Файл `*.result.json`
содержит сводку `shops`. Этот тест пока сохраняет данные локально и не отправляет
их на действующий Market API.

Первый запуск для нового PID может готовить метаданные отправителя несколько
минут до начала движения. Перехваты и метаданные изолированы по PID в LocalAppData.
При завершении запросы прекращаются, ответы дожидаются ограниченное время,
исходные обработчики восстанавливаются с проверкой. Небольшие буферы перехватов
остаются выделенными до закрытия клиента, чтобы не освободить память под
завершающимся native-вызовом.

Без `-ReadShops` остаётся исходный тест движения, описанный ниже.

Из PowerShell в `C:\broker`:

```powershell
.\test-market-walk.ps1
```

Скрипт выбирает единственный открытый клиент, строит маршрут и через пять секунд
начинает движение. Если клиентов несколько, укажи `-ClientPid 19308` с актуальным
PID. Автоматический сбор должен быть остановлен; при работающем BrokerWorker
или занятом ProcessEvent тест откажется стартовать. Окно игры остаётся открытым.

Остановка: **F8** в любом окне, **Ctrl+C** в терминале либо из другого PowerShell:

```powershell
.\test-market-walk.ps1 -Stop
```

Сначала только рассчитать маршрут, без движения и установки перехвата:

```powershell
.\test-market-walk.ps1 -PlanOnly
```

Ограниченный пробный проход:

```powershell
.\test-market-walk.ps1 -DurationSeconds 30
```

Отдельный круг вокруг четырёх перегородок лестницы и памятника с четырьмя
фонарями по его углам:

```powershell
.\test-market-walk.ps1 -ObstacleCourse
```

В результате этого режима сохраняется число пройденных контрольных сторон
каждого объекта. Без `-ReadShops` лавки и выбор цели не используются.

По умолчанию один обход, возврат к старту, предел 600 секунд. Перед очередной
командой проверяется короткий проход капсулы персонажа через геометрию клиента.
Если проход закрыт, движения нет 2,8 секунды или персонаж вышел из коридора,
тест останавливает его, добавляет локальное препятствие и строит обход к
следующему участку маршрута. После повторных неудач пропускается более длинный
участок. Предел — четыре перепланирования в одной зоне и 12 за запуск.
При исчерпании попыток, скачке координат или внешней смене цели тест завершается.
Эта логика пока находится в тестовом скрипте; рабочий сборщик не изменён.

Маршрут охватывает большинство трейдеров сохранённого снимка в радиусе 125
единиц. Это расстояние для теста прохода, не обещание доступности магазина.
Планировщик обходит прочитанную геометрию с запасом 55 единиц, считает
неизвестные BSP-участки закрытыми, скругляет повороты. Исполнитель ведёт к
упреждающей точке и обновляет направление во время движения, без остановки
на каждом узле. Случайные рывки и дрожание не добавляются.

Карта для маршрута — `maps/Giran/giran-navigation-2026-09-24.json`. Она дополняет
исходный рисунок сечениями по всей высоте капсулы и высотой пола. Резкие перепады
пола закрыты, ступеньки проверяются с ограниченным подъёмом капсулы. Каменные
перегородки остаются препятствиями. Запрос использует профиль Pawn; капсулы
других игроков исключены, NPC и статические объекты проверяются.

У планировщика и исполнителя разные запасы: при движении используется радиус
капсулы из клиента плюс 15 единиц, минимум 24. Это позволяет мягко скруглять
повороты внутри широкого коридора планирования, не считая его край стеной.

Продолжить остаток конкретного сохранённого прохода можно так:

```powershell
.\test-market-walk.ps1 -ResumeResult 'C:\путь\к\проходу.result.json'
```

Исходная карта проверяется по SHA-256; продолжение соединяется с оставшейся
частью маршрута и заканчивается в исходной точке первого прохода.
После автоматического перепланирования эта команда пока отклоняется: старая
длина пути уже не соответствует новому маршруту. Запусти новый круг.

Координаты задаются в системе мира, поэтому камеру можно вращать. Тест не
вращает её принудительно. Без `-ReadShops` трейдеры не выбираются и лавки не читаются.
Если начальная точка попала внутрь геометрического запаса, скрипт сначала
пытается коротко отойти по проверенному клиентом отрезку и заново строит путь.
Незнакомая геометрия и изменения рынка всё ещё могут потребовать остановки;
прохождение одного круга не доказывает доступность любого объекта с любой стороны.

Результаты:
`%LOCALAPPDATA%\PriceCheckCollector\research\market-walk\<PID>\`

- `*.plan.json`: точки, длина и расчётное покрытие маршрута;
- `*.jsonl`: фактические координаты, ошибка следования и события обхода;
- `*.preflight.jsonl`: короткий отход из начального геометрического запаса,
  если он понадобился;
- `*.result.json`: причина остановки, координаты, фактическое приближение
  к трейдерам снимка, число команд и контроль остановки.

ProcessEvent-мост устанавливается только на время запуска и снимается при
нормальном завершении, F8, Ctrl+C и обработанной ошибке. Не завершай Python
через диспетчер задач во время теста: это обходит `finally`. Самостоятельно
удалять файл состояния перехвата у живого процесса нельзя.

Сохранённая карта: `C:\broker\maps\Giran\giran-market-2026-09-24.html`.
Исходные данные и геометрия лежат рядом. Это снимок от 24 сентября 2026,
19:38 по Киеву; новые трейдеры после этой отметки в расчёт не добавляются.

Плавность раннего прохода подтверждена пользователем. Причина прежнего
застревания возле храма исправлена уточнением высоты пола. Контроли запросов,
неудачные промежуточные версии и результаты новых проходов записаны в
`docs/analysis/world-geometry/observations/005-capsule-avoidance.md`.

Последняя полная проверка: **5:07**, 37 523 единицы пути, **без застреваний**,
возврат в пределах 2,75 единицы от старта. Пройдено рядом с **1 614 / 1 798**
трейдерами снимка (радиус 125), выполнено 952 проверки капсулы. Фактический путь
сохранён в `maps/Giran/giran-market-walk-2026-09-24.png`.

Отдельный проход вокруг препятствий: **1:40**, все **20 / 20** контрольных углов
перегородок и постамента пройдены, застреваний нет, возврат к старту.
Схема: `maps/Giran/giran-obstacle-course-2026-09-24.png`. Проверены эти маршруты;
непрочитанные участки геометрии всё ещё требуют ограничений и контроля прогресса.
