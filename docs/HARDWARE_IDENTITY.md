# Автоматический скан и шаблоны HWID

Скан выполняется локально перед каждым запуском клиента и при открытии вкладки
шаблонов. Результаты хранятся в памяти и пересчитываются для выбранного шаблона.
В шаблоне нет списка устройств с компьютера разработчика. Общий лимит ожидания
скана — 60 секунд; ошибки отдельных источников видны в списке покрытия.

Перечисляются все доступные записи SMBIOS, узлы процессора и аппаратные профили
реестра, сетевые интерфейсы, физические диски через SetupAPI, готовые тома,
экземпляры мониторов Enum\DISPLAY, USB/HID и результаты WMI. Убраны пределы
PhysicalDrive0..15, 16 объектов WMI и первые 24 USB/HID. PCI HardwareID показываются
все, включая совместимые ID; для них подмена пока не заявлена.

## Значения клиента

Каждый процесс получает значения своего шаблона. MAC вычисляется из MAC шаблона
и GUID адаптера; порядок перечисления не влияет на результат. EDID вычисляется
из UUID шаблона и полного vendor\instance, поэтому одинаковые модели мониторов
различаются. Меняются числовой и текстовый серийные номера и контрольная сумма
базового блока. Производитель, модель, имя, режимы и расширения EDID сохраняются.
Повреждённые и неполные EDID остаются без изменений и отмечаются отдельно.

WMI MAC совпадает с сетевыми API для того же адаптера. WMI SerialNumberID
монитора совпадает с текстовым серийным номером EDID с учётом длины массива.
Сохраняются границы, длина и тип SAFEARRAY. Поддержаны VT_I4 и VT_UI2;
для WMI uint16 Microsoft документирует [Automation VT_I4](https://learn.microsoft.com/en-us/windows/win32/wmisdk/numbers).

## Покрытие путей чтения

| Источник | Агент клиента | Новая сборка драйвера |
| --- | --- | --- |
| MachineGuid, HwProfileGuid, ProductId, SusClientId, SQM MachineId, VideoIdentifier, ComputerName, InstallDate, модель/ревизия CPU | NT QueryValue/EnumerateValue; через них RegQueryValueEx A/W, RegGetValue A/W, RegEnumValue | Registry QueryValue/EnumerateValue |
| Монитор EDID | Чтение/перечисление значения EDID реестра, WmiMonitorID.SerialNumberID | Чтение/перечисление значения EDID реестра |
| UUID и серийные номера системы, платы, корпуса, CPU, памяти | GetSystemFirmwareTable и поддержанные WMI Get | Нет системной подмены SMBIOS |
| MAC интерфейсов | GetAdaptersAddresses, GetAdaptersInfo, поддержанные WMI Get | Нет системной подмены сетевых IOCTL |
| Серийный номер диска, GPT GUID / MBR signature | Поддержанные синхронные DeviceIoControl; WMI SerialNumber | Нет системной подмены storage IOCTL |
| Серийный номер тома | GetVolumeInformation A/W, WMI | Нет системной подмены |
| USB/HID instance ID | Поддержанные SetupAPI/CM и WMI Get | Нет системной подмены |

Покрытие ограничено указанными путями. Не подтверждены произвольные прямые
системные вызовы вне поддержанных registry callbacks, QueryMultipleValue,
альтернативные WMI интерфейсы/сериализация, чтение EDID_OVERRIDE по номерам блоков,
асинхронные storage IOCTL и собственные запросы стороннего драйвера к оборудованию.
Значения, которые лишь обнаружены, и недоступные источники не помечаются как
успешно подменённые. Проверка тестового процесса не доказывает покрытие всех
запросов клиента или античита.

## Драйвер: изоляция и общий набор

Добавлен IOCTL SET_PROCESS_IDENTITY 0x812 при сохранении версии протокола 3.
Контракт 1048 байт синхронизирован между lu4_protocol.h и Lu4Device.ProcessIdentity.
Регистрация выполняется после привязки маршрута, пока корневой процесс suspended.
Учитываются объект процесса, PID, время создания, владелец маршрута и GUID профиля;
повторная привязка того же процесса к другому набору отвергается. Дочерние процессы
наследуют набор до запуска первого потока. Таблица ограничена 64 процессами вместе
с дочерними; исчерпание ресурсов прерывает создание нового наследника.

Первый зарегистрированный клиент задаёт общий набор для запросов процессов,
которые не принадлежат зарегистрированным клиентам. Этот набор остаётся тем же
до завершения всех приложений-контроллеров, даже если первый клиент уже закрыт.
Запросы зарегистрированных клиентов используют собственные наборы. После
регистрации контроллеры видят исходные значения для нового скана. Общий режим охватывает только строки
таблицы с поддержкой драйвера; он не превращает firmware/network/storage ответы
в системную подмену. Реестр и оборудование постоянно не переписываются.

Используется [документированный registry filtering callback](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/filtering-registry-calls).
Altitude 385421.918 предназначен для разработки и требует корректного выделения
перед распространением производственного драйвера.

**Статус 2026-09-30:** агент, приложения и кандидат драйвера собираются. Новый
драйвер не загружен и не прошёл живую проверку registry callback, наследования и
общего набора. Проверенный артефакт и закреплённый хеш загрузчика не заменены:
см. [правило продвижения драйвера](../native/LU4Memory/README.md#verified-baseline).
При старом драйвере IOCTL возвращает unsupported; приложение явно показывает
режим подмены агентом. Другие ошибки регистрации блокируют запуск.

## Проверки

```powershell
.\tests\HardwareIdentity.Smoke\build.ps1
.\native\LU4Memory\build.ps1
.\build.ps1 -SkipBroker -SkipPackages -OutputDirectory workspace\hwid-verification\Collector -LauncherOutputDirectory workspace\hwid-verification\Launcher
```

HardwareIdentity.Smoke проверяет совпадение C#, native C++ и кода EDID драйвера,
сохранность режимов/расширений, checksum, идемпотентность, некорректные EDID,
стабильность MAC на 400 адаптерах. Два отдельных процесса устанавливают полный
набор обработчиков агента, выполняют VerifyIdentityHooks, чтение GUID через
Win32/NT в четырёх форматах, size-only/короткий буфер, перечисление и WMI.
Проверены пять WMI MAC и один WMI монитор этого компьютера; локальный скан —
119 строк, один EDID, пять сетевых интерфейсов. Реальные идентификаторы в этих
проверках не записываются в реестр. Также проходят Launcher.Smoke и стандартный
LaunchProtection.Smoke без загрузки нового драйвера.
