# Launch template UI review (2026-09-23)

The template editor previously put 20 HWID fields before proxy settings. Its proxy panel bound `IsEnabled` to `LaunchTemplate.ProxyEnabled`, but that property had no change notification. Checking the proxy box changed the model while leaving the fields disabled until the selected template was refreshed. A global `TextBlock` foreground style also forced light text into WPF's light ComboBox items, hiding character and login server choices.

The editor now places the optional proxy first, binds field availability directly to the checkbox, and groups generated identifiers and local scan results in expandable sections. The scan section opens after a successful scan. The app's user-facing labels, status text and validation errors are in English; only legacy Russian template-name strings remain in migration checks. Existing automatically named templates are renamed to English on load. Text boxes keep light text on a dark surface; ComboBox items use dark text on a light surface; checkboxes have explicit light text.

Verification: `build.ps1 -SkipBroker` and `dev.ps1 run` succeeded. `tests/CollectorUi.Smoke` instantiated the WPF view, checked that the proxy fields enable immediately, entered host/port/username/password, invoked Save and verified the saved model. Its offscreen render (`workspace/ui-template-preview.png`, ignored) was inspected for contrast and layout. The release Collector restarted as PID 10804 with the WFP driver running. The user's desktop was occupied by another app, so no direct screenshot of the main Collector window was captured in this pass.
