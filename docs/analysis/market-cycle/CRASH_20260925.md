## Safety repair and uncertainty

`process_event_shop_capture.uninstall` and the broker counterpart restored the
`ProcessEvent` entry point and immediately freed the executable trampoline and
its history data. The shop uninstall may fail to suspend the protected process;
an already-entered game thread can still be using that memory. This is a real
use-after-free risk and the route completion timestamp matches the crash second,
but the crash report has no symbols proving it was the specific trigger.

Both uninstall paths now restore the prologue and retain those allocations until
the game exits. The shop route writes already captured results even if cleanup
raises, so the C# coordinator can spool valid captures before reporting failure.
There is a memory tradeoff: about 128 KiB per price route plus roughly 2 MiB per
broker capture can remain mapped. Track private bytes during a long live run and
design safe reuse or a controlled client restart before declaring an indefinite
soak stable.

The old collector was stopped after the game exited. `build.ps1` rebuilt the
packaged worker and desktop successfully; 21 BrokerWorker Python tests and
`py_compile` passed. The new release was launched at 18:50 with collector 8448
and game 9084. The first center attempt hit the previously known 9x23 capsule
startup-readiness guard while the game was still loading; normal retry continues.
