# PID-scoped WFP proxy for LU4 (2026-09-23)

## Implementation

The Collector now uses its LU4Memory driver for IPv4/TCP connect redirection at `FWPM_LAYER_ALE_CONNECT_REDIRECT_V4`. The driver registers a WFP callout lazily, keeps at most 16 PID-to-listener routes, and clears routes on process exit. Only the bound final `lu4.bin` PID is redirected. The host listener receives the original destination through `SIO_QUERY_WFP_CONNECTION_REDIRECT_CONTEXT`, carries WFP redirect records to its outgoing socket, authenticates an HTTP CONNECT with the configured proxy, and relays bytes. The game retains its original Winsock receive path and `clmods64.dll` receive transform. HWID agent hooks and the existing LU4Memory-backed radar remain separate.

Source: `native/LU4Memory/driver/proxy_redirect.inc`, `src/PriceCheck.Collector/Services/ProxyTcpBroker.cs`, `src/PriceCheck.Collector/Services/ClientProcessService.cs`. The old named-pipe `recv` broker remains in source as research code but is no longer selected by template launches.

The WFP driver build needs `/INTEGRITYCHECK` for `PsSetCreateProcessNotifyRoutineEx`. It also must call `FwpmEngineOpen0` at PASSIVE_LEVEL; a `KMUTEX` guards registration without raising IRQL. `FWPS_CONNECT_REQUEST0.localRedirectContext` ownership transfers to WFP after `FwpsApplyModifiedLayerData0` on Windows 8 and newer. See [Microsoft: connect redirection](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/using-bind-or-connect-redirection), [connect request fields](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fwpsk/ns-fwpsk-_fwps_connect_request0), [process callback requirement](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-pssetcreateprocessnotifyroutineex), and [/INTEGRITYCHECK](https://learn.microsoft.com/en-us/cpp/build/reference/integritycheck-require-signature-check).

## Observed limitation

The first local-proxy world screenshot also showed an Active Anticheat Service dialog claiming Windows is in Test Mode. `bcdedit /enum {current}` at the time showed `testsigning No` and `nointegritychecks No`; the loader had restored DSE immediately before starting the game. We did not click its proposed system-setting action. A later direct control run and a later local-proxy world run on the already loaded release driver had **no dialog**; the latter screenshot is ignored `workspace/settled-wfp-world.png`. This points to a transient condition around driver loading, but the precise trigger and safe interval are unconfirmed. New installations should be checked for this behavior.

The current filter covers IPv4/TCP only. It does not redirect UDP or IPv6. The test client used IPv4/TCP for login and world. The driver and client agent are tied to the known LU4 and Windows build behavior; other machines and anticheat versions require validation.

## Authenticated proxy login failure and fix (2026-09-23)

The saved Gamma and Black templates had a literal backslash before the underscore in each proxy username. Replaying HTTP CONNECT to the observed LU4 login endpoint (`external-address-2:2108`) with the saved, DPAPI-protected passwords returned `407 Proxy Authentication Required` for both templates. Removing only that backslash returned `200 Connection Established` for each. The two usernames were corrected in `%LOCALAPPDATA%\PriceCheckCollector\launch-templates.json`; the encrypted passwords were left unchanged. A local backup is in ignored `workspace/launch-templates.before-proxy-login-fix.json`. No credentials were recorded in this note or test logs.

`ClientProcessService` now calls `ProxyTcpBroker.VerifyUpstreamAsync` before starting a proxy-enabled client. It sends an authenticated CONNECT to that login endpoint and reports a clear `407` template error if the proxy rejects the credentials. The mock-proxy test in `tests/ProxyRedirect.Smoke` passed for both `407` rejection and `200` acceptance. The check is specific to the currently observed LU4 login endpoint; if the server address changes, update the probe destination.

After `dev.ps1 run` built and restarted the Collector, `tests/ClientLaunch.LiveSmoke --auto-login-black-template` loaded the saved Black profile and bound template, launched final LU4 PID 17528, installed the HWID agent and driver receive hook, and completed programmatic account, Gamma, and character selection. The WFP broker recorded HTTP 200 for both login port 2108 and world port 7782, followed by sustained bidirectional world traffic. A local screen capture (`workspace/black-proxy-login-17528.png`) showed the in-world scene behind the Codex window. The smoke test held the client for its observation interval and exited successfully, terminating only that test PID. The release Collector and driver remained running.
