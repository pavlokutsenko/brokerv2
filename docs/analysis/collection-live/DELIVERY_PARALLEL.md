`LocalCycleStore` now uses up to eight HTTP lanes. It claims each durable operation under the SQLite lock, makes the request without that lock, and only deletes after an accepted response. A claimed operation cannot be sent twice. The next operation for the same `traderKey` waits for its predecessor, including when the predecessor is backing off after a transport failure. Distinct traders can upload concurrently. State, then price, then broker remains the selection priority across traders. A single guarded sender task owns the lanes, including shutdown; cancellation leaves pending operations in SQLite.

The original all-kind priority query took ~21 ms per claim against the live 8,913-row outbox. Separate indexed queries for state, price, and broker took ~0.006, 0.003, and 0.107 ms respectively on an in-memory copy of the same read-only database. The new `(kind,next_attempt)` index is created idempotently by the store. No live database was modified for this measurement.
