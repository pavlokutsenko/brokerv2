# Early `0x222044` response: block map and first-client control

The root-only opt-in `DeviceIoControl` capture recorded a complete 0x4BA-byte
`0x222044` reply from Black before login. A test-only 16-byte FNV64 map was
added behind `PRICECHECK_EARLY_044_BLOCKS=1`. Repeated prelogin launches with
Gamma already in the world, including one launch that regenerated all Black
template identifiers, shared exactly 40 of 76 block hashes: indices 1-7,
9-40 and 75. The other blocks varied between launches. No conclusion about
plaintext hardware values, encryption or the server check follows from a
matching block hash.

Three initial unmodified controls stopped the normal Gamma client, captured Black at the same
prelogin gate, then restored ordinary Collector/Gamma and its established
proxy tunnel. The three **solo** replies shared the same 40 block indices with
each other. Against any captured **paired** reply, they shared only 39: block
40 (offsets 0x280-0x28F) changed. Direct comparison of ignored raw captures
showed that within this block only byte offset `0x28D` differed: `0x58` solo
and `0x60` with the first Gamma active. A second paired raw capture repeated
`0x60`; all three initial solo block hashes matched. These observations
were correlated with first-client presence **in those runs only**. The
remaining variable regions still differed between runs.

A stricter sequence in one driver session disproved the simple process-count
interpretation. After stopping normal Gamma and waiting ten seconds until no
`lu4.bin` process remained, a solo Black prelogin capture had the **same
block-40 hash as the earlier paired captures**, corresponding to `0x60` if
only byte `0x28D` differs. A second Black was then held at the prelogin gate;
its own captured block 40 was also `0x60`, and a third Black launched while
it was paused again had `0x60`. The first run of this two-prelogin control
likewise gave `0x60` for its second client, while its first client's hash was
a third value consistent with `0x64`; the first normal Gamma had just been
stopped without a settling wait. Thus `0x28D` varies with launch history or
some other runtime state. It does **not** reliably encode whether another
client is currently open or already in Gamma. The buffer's format and any
role in the 69-byte world request remain unknown.

Forty stable blocks had distinct hashes, and none was found verbatim in the
on-disk `clmods64.dll` or `active64.sys`, the first client's loaded clmods
image, or the loaded driver image in read-only scans. The response may be
generated or transformed in memory. These scans cannot identify its format.

A temporary root-only callback then set byte `0x28D` to `0x60` in a solo Black
reply after the real driver call. A diagnostic counter confirmed one write.
Black remained at the Active Anticheat window and did not reach the prelogin
gate within 55 seconds. A preceding full-login attempt with the same setting
also never reached agent readiness; its initial patch-count trace was
unreliable because the counter was sampled before the callback finished.
After fixing that diagnostic ordering and offset, the prelogin attempt
verified the write. **Crucially, the patched build's pre-write capture had a
third block-40 hash**, consistent with `0x64` at byte `0x28D` if only that byte
differs from the unmodified solo reply. An immediately following unmodified
solo capture returned to the earlier `0x58` hash. The original byte in the
patched attempt was therefore not validated as `0x58`; the callback's code
layout or another changed runtime condition may have affected the reply.
The startup failure cannot be attributed to a clean `0x58`-to-`0x60` edit.
A paired `0x60`-to-`0x58` world test was **not run** because this control is
ambiguous. No conclusion about integrity checking or the byte's semantics
follows from the mutation attempt.

The temporary raw-response writer and mutation branch were removed. Raw
responses and scripts remain ignored under LocalAppData and `workspace/`;
tracked files contain only aggregate findings. The normal Collector/Gamma
was restored after both solo controls. Two clients in Gamma at once remain
unverified.
