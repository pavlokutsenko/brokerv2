# Проверки HWID и прокси в Launcher / Collector

В обеих оболочках запуск игры требует выбранного шаблона с включённым HWID.
HTTP CONNECT-прокси используется только при ProxyEnabled=true. При снятой
галочке его сохранённые поля не валидируются, upstream не проверяется ни перед
запуском, ни периодически, а CONNECT/авторизация не отправляются.
Пустой шаблон, отключённый HWID, недоступный включённый прокси или несовместимый драйвер запрещают запуск. Настройки
пользователя не включаются и не перегенерируются автоматически.

## Индикаторы в Launch

- **HWID · не проверен** — агент ещё не подтвердил подмену.
- **HWID · проверен, ожидание входа** — реальные ответы MachineGuid, volume
  serial, SMBIOS UUID и MAC соответствуют шаблону; поддерживаемый игровой
  hardware layout проверен. Envelope и отличие world identity от исходной
  проверяются при фактическом world handshake.
- **HWID · применён в мире** — агент переписал и успешно передал известный
  69-байтный world handshake. Его идентичность и номер применения соответствуют
  текущему CONNECT-соединению мира; через этот туннель прошли данные в обе стороны.
- **ПРОКСИ · защита активна** — драйвер подтверждает обязательный маршрут,
  запрет прямых соединений и владельца PID. Показаны успешные игровые CONNECT
  и переданные байты; проверочные CONNECT не увеличивают эти счётчики.
- **ПРОКСИ · выключен в шаблоне** — нейтральный индикатор. HTTP-прокси не
  используется; успешная проверка HWID не требует ProxyReady.
- **HWID · проверка прервана** — запуск прервался по другой причине;
  приложение не выдаёт это за обнаруженное несовпадение HWID.
- **ОШИБКА** — причина видна рядом и в журнале. Клиент завершается; Collector
  отключает reader/сбор. Автоматический recovery после ошибки защиты отменяется.
  Исправьте шаблон/прокси/драйвер и запустите профиль заново.

Короткий отпечаток HWID относится к profile ID и выбранному world seed.
Сохранённый seed остаётся прежним; только Regenerate или RotateEachLaunch
меняют его по выбранной пользователем настройке.

## Когда выполняются проверки

До создания процесса проверяются HWID и возможности LU4Memory. Параметры
прокси и CONNECT 200 до login-сервера проверяются только при включённой опции.
Launcher создаёт процесс через
CreateProcessW в приостановленном состоянии, устанавливает WFP-маршрут и
только затем разрешает выполнение. Дочерние процессы наследуют маршрут
в kernel create callback до запуска первого потока. Другие игровые PID
не принимаются как наши клиенты.

После появления окна агент читает результаты уже установленных API hooks
и проверяет известную версию/структуру игровых hardware данных. До этого
передача login/world соединений через relay удерживается. Перед автовходом
и reader setup запуск повторно требует подтверждения HWID/прокси.
Native login повторяет проверку перед аккаунтом и сервером; выбор персонажа
требует успешной подмены в его world handshake. После выбора персонажа
managed launch требует подтверждённый world-туннель; включение сбора тоже
проходит этот барьер. Ручной вход проверяется теми же socket hooks и монитором.

Мониторы controller/agent работают каждые 500 мс. Проверяется WFP-маршрут,
ответы API, игровой hardware layout и heartbeat. До первого world handshake
его ещё не сформированный envelope не считается ошибкой. Счётчик отклонённых
соединений показывает работу запрета; сам по себе он не означает потерю защиты.
Потеря controller lease на 5 секунд закрывает native send/login и завершает
игру; смерть контроллера также отзывает разрешённый relay в драйвере.
Включённый прокси повторно проходит CONNECT-проверку каждые 10 секунд. Ошибка туннеля
завершает клиент; новый world CONNECT должен подтвердить HWID и двусторонний
обмен за 20 секунд. Подтверждение предыдущего мира не разрешает новое соединение.
Ротация и recovery создают нового клиента через весь этот путь.

## Границы гарантии

IPv4/TCP игровых процессов перенаправляется через локальный relay в выбранный
HTTP CONNECT-прокси. Разрешён только точный TCP endpoint этого relay;
другие прямые соединения, UDP/raw и IPv6 блокируются. Отзыв маршрута или смерть
контроллера оставляет запрет трафика до выхода процесса. Windows и остальные
приложения продолжают использовать свои обычные сети. Это не общесистемный VPN;
делегированные системной DNS-службе запросы не покрываются per-PID WFP-маршрутом.

При ProxyEnabled=false тот же локальный relay соединяется непосредственно с
исходным IPv4 endpoint. Он сохраняет владение дочерними PID, блокировку входа
до проверки HWID и соответствие world generation реальному двустороннему TCP.
Проверка внутреннего маршрута LU4Memory остаётся частью контроля HWID;
внешний HTTP-прокси и его проверки отсутствуют. UDP/raw и IPv6 по-прежнему
запрещены для этих игровых PID. MMF required flags равны 1 (HWID), при
включённом прокси — 3. Native lease отвергает все остальные комбинации.

Проверяются существующие поддерживаемые identity hooks и подмена игрового
world handshake. Самостоятельные WMI/kernel/firmware чтения вне этих hooks
не считаются покрытыми. Неизвестный игровой binary/layout отклоняется.
Новые игровые адреса памяти и протоколы этой задачей не исследовались.

## Выполненная проверка 27 сентября 2026

Пользовательские настройки не менялись. До live-проверок прошли:

- LaunchProtection.Smoke: барьеры до login/reader и после персонажа, ошибки
  с завершением клиента, отсутствие запуска без обязательного шаблона;
- реальные WFP-тесты: authenticated CONNECT/echo, прямой IPv4/IPv6 TCP,
  UDP без доставки, запрет raw ICMP bind, дочерний процесс, отзыв relay, смерть controller,
  установка политики до первой инструкции suspended процесса;
- managed monitor: native ошибка, потеря agent heartbeat, снятие WFP route,
  отказ прокси; повторный world-туннель отвергает прежнее подтверждение;
- native guard: неверные mapping/PID/birth, неподтверждённый HWID,
  устаревший world/lease, запрет send/login; watchdog прекращает тестовый
  процесс при потере controller, HWID hooks или игрового hardware layout;
- ClientLaunch.Smoke: реальные Windows identity hooks в отдельном процессе;
  DriverConcurrency.Smoke: 4000 чтений двух тестовых PID через восемь handles.

Native watchdog probe использует подставные identity/layout функции;
реальные API hooks проверяет отдельный ClientLaunch.Smoke.

Первые live-попытки полной комбинации выявили закрытие клиента после начала
входа. По просьбе пользователя
проверки добавляются по одной в отдельном тестовом launcher: прежняя
последовательность запуска, затем защита маршрута до первой инструкции,
однократная проверка HWID API и периодическая проверка тех же API — каждый
из этих этапов прошёл Gamma/world. Затем полный штатный путь прошёл персонажи
0 и 1: с reader перед входом и без него. Windows API hooks, подмена игрового
69-байтного handshake, двусторонний world-трафик и повторные проверки
подтверждены. Отзыв маршрута остановил клиент и запретил следующий вход.
Настройки пользователя не изменялись. Точная причина ранних закрытий не
доказана; не приписывайте результат снятию какого-либо одного барьера.
Журналы и подробности:
[launch-protection/RESUME.md](analysis/launch-protection/RESUME.md).

После исправления необязательного прокси проверены оба режима на сохранённом
Gamma/profile и «Template proxy 2». В памяти теста при выключенном прокси
подставлены заведомо невалидные устаревшие поля; запуск и периодические проверки
их игнорировали. Слоты 0/1 вошли в мир: PID 20848 и 15692, HWID API/world=true,
отпечаток E333C54BA1BC, CONNECT=0, ProxyRequired=false. Повтор с включённым
тестовым прокси также прошёл оба слота, CONNECT=6, ProxyRequired/ProxyReady=true.
Оба прогона проверили непрерывный монитор и остановку при отзыве своего relay;
последующий character gate отвергнут. Профили/шаблоны на диске не изменились.
Журналы: `workspace/launch-protection-live/optional-proxy-direct.log` и
`workspace/launch-protection-live/optional-proxy-enabled.log`.

LaunchProtection.Smoke --wfp подтвердил direct TCP echo без HTTP CONNECT и
отсутствие upstream probe после 11 секунд, сохранив остановку при HWID error.
Native tests принимают только required flags 1/3; UI smoke подтверждает
нейтральный индикатор отключённого прокси. Финальные ZIP сборки
`d013b2d8cda841608edae1fd680d25a5` проверены после распаковки и через реальные
корневые apphost/WPF. Драйвер не изменялся; agent/login пересобраны с lease flags 1/3.
Ручной вход, одновременные защищённые игровые клиенты и перенос на другой
ПК/чистую Windows требуют отдельной live-приёмки.
